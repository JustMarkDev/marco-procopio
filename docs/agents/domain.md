# Domain docs

This is a single-context repository.

Before exploring or changing the codebase, read:

- `DECISIONS.md` for the current product, technical, and quality decisions;
- root `CONTEXT.md` if it exists;
- relevant ADRs under `docs/adr/` if that directory exists;
- documentation linked by the active local issue.

Proceed silently when optional context files do not exist. Create or revise domain vocabulary and ADRs only when a real decision is made through `/domain-modeling` or `/grill-with-docs`.

Use established project terminology in issues, tests, code, and review findings. Surface conflicts with `DECISIONS.md` or an ADR instead of silently overriding them.
